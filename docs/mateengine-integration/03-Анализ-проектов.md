### SoW: что уже есть и чего нет

1. AIFactory выбирает provider по `conversation_method`; `OpenAIProvider` использует OpenAI-compatible `base_url`, модель и ключ из SoW configuration. `DeepSeekProvider` зашит на официальный endpoint — это не использовать автоматически.
2. Стандартный text-chat path находится в `app/gui/interface_signals.py:handle_user_message`: там строятся prompt blocks, вызывается `provider.generate_stream`, обновляется GUI и после ответа отдельно запускается memory update. `sow_system_signals.py` — другой Qt-bound voice/call/companion controller, не headless chat entrypoint.
3. Текущего headless backend нет: `main.py` создаёт QApplication/MainWindow/event loop, а `Soul_Of_Waifu_System` создаёт Qt UI/layouts и desktop workers. Headless extraction — обязательная часть Phase 0.
4. Storage paths относительны current working directory: `app/configuration/characters.json` хранит chat history; `.soul/<character>/chats/<chat>/memory` хранит MEMORY/USER/topics/backups/log; attachments находятся под `app/data/.soul`. Нужен явный data root.
5. Memory update запускается отдельной asyncio task до финальной записи полного user/assistant turn. Для интеграции нужен serialized canonical commit boundary.
6. Soul Companion использует тот же AIFactory, но approval gate привязан к Qt banner; MCP fallback в текущем `_execute_tool` вызывается без этого gate. Tools/MCP/heartbeat/OS actions отключить в MVP.
7. На Linux есть неподдержанные/непроверенные paths: idle-time функция определена только внутри `if sys.platform == "win32"`, media control может вернуть success без действия, AppControl/PowerShell Windows-only, STT hardcoded на CUDA/float16. Нельзя заявлять весь Soul Companion Linux-ready.
8. `web_server.py` имеет FastAPI/WebSocket, но WebBridge Qt-coupled; его токен логируется, WebSocket допускает query token, а GUI startup bind-ит `0.0.0.0:8000`. Это не готовый secure MateEngine API.

### MateEngine: что уже есть

1. Active Linux/overlay path — `LLMUnitySamples/ChatBot.cs` + `undream.llmunity.Runtime.dll`; ChatBot вызывает `LLMCharacter.Chat`. Это нужно отключить как LLM/history owner в MVP и заменить SoW client callback.
2. Ollama path из `Assets/ollama-unity` — старый альтернативный путь, отсутствующий в Linux/overlay и отключённый в основной сцене; не проектировать вокруг него.
3. `InputBubble.FixCaretSorting()` имеет опасный путь `GameObject.Find(...).GetComponent<Canvas>()` без null-check; текущий source не содержит обещанного null-safe fix.
4. `AvatarRandomMessages` создаёт независимые локализованные `RandomBubble`; его нужно отключить/сделать visual-only в MVP, иначе будет второй producer реплик.
5. `AISystemPromptBinder` читает/пишет `ZomeAI_prompt.txt`; отключить live-save в MVP, чтобы не было второго prompt owner.
6. `AvatarHideHandler` содержит edge snap/hide и window movement; его не нужно связывать с chat transport.
7. Shoji bridge — отдельный compositor IPC с env gate `MATEENGINE_SHOJI_BRIDGE`; не смешивать его с application chat protocol.
8. `UniversalBlendshapes` предоставляет потенциальную точку для будущего emotion/viseme mapping, но consumer SoW emotion event не найден; audio-to-lipsync не готов.

### Provenance caveat

Статический аудит показал, что active `Assembly-CSharp.dll` имеет SHA-256 `bfdb542115744418c1e5ffb525a7a90489f586a74b5eebca7f3ac8ab0cb214bc`, тогда как `Linux/builds/linux-3.4/MateEngineX_Data/Managed/Assembly-CSharp.dll` имеет `ff4b16901814e08efed2cfe0b824e3ea5f929d2c3326d2674e9472cc023657da`. `MateEngine.ShojiBridge.dll` совпадает: `ffb1c856ecffe520caf6826449ded8995ffcfe52feb6f7cbf2b505e05d10d66b`.

Следовательно, active player нельзя считать полностью идентичным default source build. До разработки нужно зафиксировать provenance active Assembly-CSharp или строить candidate на отдельной подтверждённой базе. Это неизвестность, а не доказательство повреждения.
## Важное разделение

Краш при чате/уведомлении и edge/window crash — разные контуры до доказательства обратного. Первичная подозрительная точка chat path — `InputBubble.FixCaretSorting`; edge path — `AvatarHideHandler`/bridge/window calls. Интеграция должна иметь отдельные regression gates.
